XSS란?

공격자가 넣은 스크립트가 다른 사람 브라우저에서 그대로 실행되는 취약점입니다.

Cross-Site Scripting(XSS)은 공격자가 입력한 HTML/JavaScript가 필터링 없이 다른 사용자의 브라우저에서 그대로 실행되는 취약점입니다. 세션 쿠키 탈취, 피싱 화면 삽입, 페이지 변조 등에 악용될 수 있습니다.

종류

Reflected, Stored, DOM-based — 세 가지가 있고 이번 실습은 Reflected/Stored를 다룹니다.

  • Reflected XSS — 입력값이 즉시, 그 페이지 응답에만 그대로 반영됨 (예: 검색 결과 페이지)
  • Stored XSS — 입력값이 서버에 저장되었다가, 이후 그 페이지를 보는 모든 사용자에게 노출됨 (예: 댓글, 게시글)
  • DOM-based XSS — 서버를 거치지 않고 브라우저 쪽 JS가 직접 입력값을 DOM에 반영할 때 발생 (이번 실습에서는 다루지 않습니다)
입력값이 HTML에 들어가는 과정

입력값이 그대로 HTML 문법의 일부가 되어버립니다.

서버 코드는 보통 이런 식으로 입력값을 HTML 문자열에 직접 이어 붙입니다.

echo "<p>검색어: " . $_GET['q'] . " 에 대한 결과가 없습니다.</p>";

$_GET['q'] 자리에 무엇이 들어오든 그대로 HTML 문법의 일부가 됩니다.

정상 입력
검색어: 노트북

↓

<p>검색어: 노트북
 에 대한 결과가 없습니다.</p>
공격 입력
검색어: <script>alert('XSS')</script>

↓

<p>검색어: <script>alert('XSS')
</script> 에 대한 결과가...</p>

오른쪽은 입력값 자체가 하나의 실행 가능한 태그가 되어, 브라우저가 이 페이지를 렌더링할 때 스크립트로 해석하고 실행해버립니다.

취약한 코드의 특징

이스케이프 없이 입력을 그대로 HTML에 출력하는 게 핵심 문제입니다.

  • 사용자 입력을 이스케이프 없이 그대로 HTML에 출력한다
  • <, >, ", ' 같은 HTML 특수문자를 엔티티로 변환하지 않는다
  • 특정 태그(<script>)만 막으면 안전하다고 착각한다 (다른 태그/속성으로 우회 가능)

특정 키워드를 막는 블랙리스트 방식은 보조적인 방어책일 뿐입니다. 근본적인 방어는 출력 시 HTML 엔티티 인코딩(이스케이프)을 하는 것입니다.

공격 원리 & 방어 개요

출력할 때 이스케이프하면, 브라우저는 그걸 태그가 아니라 글자로 봅니다.

입력값 삽입 → 브라우저가 HTML/스크립트로 해석 → 공격자가 작성한 코드가 실행됨

핵심 방어는 출력 시 이스케이프(HTML Entity Encoding)입니다. <를 &lt;로 바꾸면, 브라우저는 그걸 태그가 아니라 그냥 '글자'로 표시합니다. 자세한 대응표는 실습 후 정리 섹션에서 확인하세요.

권장 순서: Lv.1 → Lv.2 → Lv.3 → Lv.4 → Challenge (순서대로 하지 않아도 자유롭게 이동할 수 있습니다)

정리 — 공격 유형과 방어

    
🎉 여기까지 오셨다면 XSS의 핵심 원리와 방어법을 한 바퀴 다 둘러본 거예요.

    

      
취약점문제방어

      
Reflected XSS (Lv.1)입력값이 그대로 응답 페이지에 출력됨출력 시 HTML 이스케이프

      
Stored XSS (Lv.2)저장된 입력이 모든 열람자에게 노출됨저장/출력 시 이스케이프 + CSP

      
블랙리스트 필터 (Lv.3)특정 태그만 막아도 다른 속성/태그로 우회됨화이트리스트가 아닌 이스케이프 자체를 신뢰

    

    
가장 근본적인 해법은 출력 시 HTML 엔티티 인코딩입니다. Lv.4에서 확인했듯, 입력값이 태그로 해석되지 않는 순간 어떤 페이로드를 넣어도 안전합니다.

    

      
심화: XSS가 뚫려도 피해를 줄이는 방법

      
    
        
  • CSP(Content-Security-Policy) — 허용된 출처의 스크립트만 실행되도록 브라우저 차원에서 제한
    • 
        
  • 쿠키에 HttpOnly 속성 — XSS가 성공해도 JavaScript로 쿠키(세션)를 읽어가지 못하게 함
